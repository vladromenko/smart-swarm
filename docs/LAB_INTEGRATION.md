# Homebrain Lab project plugin

The Smart Swarm facade implements `homebrain.lab.v1` over JSON lines. It owns scientific state and calls the existing native Studio and Explorer operations. The common Homebrain UI imports `smart_swarm.lab_api.HomebrainProject` or keeps a single `python -m smart_swarm.lab_facade` process open with `PYTHONPATH=src` and `SMART_SWARM_CONFIG` pointing to the installation's configuration. Native services and their environments retain control ownership.

The protocol accepts `descriptor`, `tasks`, `snapshot`, `action`, `operation`, `events`, `progress`, `reconcile` and `jobs`. Each request is one JSON object with `id`, `method` and `params`. Responses include the request ID and result. Canonical schemas copied from the integration owner's published contract are in `schemas/homebrain.lab.v1`. Example messages are in `fixtures/lab`. Integer revisions map durably onto the exact scientific journal digest. The domain schema remains separately available in `schemas/homebrain.lab.v1.json`.

Select `station-setup` first, then `component-pilot-1` when the attended check is current. The component pilot uses Studio independently of mobile readiness. `tasks` accepts `group`, `offset` and `limit`. Groups include `station_setup`, `component_pilot`, `development`, `study` and `paired_control`. The study allocation contains 160 train, 40 validation and 120 test histories plus 24 paired controls with two histories each. Its 78 source groups remain within their assigned split. The four technical attempts and 24 development stories retain their own allocation. Attempt quotas and accepted histories are distinct. The initial study allocation is frozen before capture. Failed or incomplete study attempts leave a coverage deficit requiring reviewed replacement allocation, with the original attempts retained.

An action supplies `project_id`, `session_id`, `target_id`, `action`, `expected_revision`, `idempotency_key` and typed `arguments`. The current session ID equals the project task ID. Reusing a key returns its prior result even after the task moves forward. Reusing it with different data fails. Stale revisions fail before dispatch. The plugin persists a pending operation before submitting the isolated worker and serializes project mutations. Native resource and recorder admission remain with the installed services. A worker interruption produces an unknown outcome, and the plugin requires native/project receipt reconciliation before another side effect.

`Start` calls the existing staged `begin` with the selected online or blind offline mode. `Start recording` requires `explicit_user_start=true` and calls Studio's native start route with its STOP generation. `Finish recording` calls native `end`, which requests durable save. The queued acknowledgement supplies no scientific admission. `Stop recording` requires `explicit_user_stop=true` and invokes the native STOP route only for this task's dataset. `Start mobile` binds the completed exact episode before requesting Explorer capture. `Grant relocation` checks the protocol lead-in and recorded RGB, then claims the prompt once. `mark` records the phase, assistance and directly observed result. `predict` waits for native readback and seals the policy input. `reveal` requires the post-seal step. Review uses the existing native export, corpus readers and motor-prefix review.

The schema and facade transport exclude arbitrary shell commands. Operator speech, UI memory and evaluator data have no policy-input field. Original role projection, F6 withholding and evaluator namespaces remain enforced by the recording readers. Every model input still comes through those readers.

The private registration is published to `HOMEBRAIN_LAB_HANDOVER_DIR/smart-swarm.json`, defaulting to `~/.local/share/homebrain-lab/handover/smart-swarm.json`. It records the actual checkout, commit, interpreter, schema, configuration and validation receipts. `integration-owner.json` appeared during implementation and supplied the concrete canonical schemas. The inspected common UI currently uses a read-only adapter and its own prompt workflow. Its contract consumption and real-service journey require the integration owner. This checkout does not edit or deploy that UI.

## Station qualification

The initial schematic illustrates a table and floor without metric geometry. Studio's existing fixed top camera supplies the evaluator clip. No physical viewpoint has been verified for a floor destination. Distributed actions remain blocked until the station profile can prove each witness's view and the evaluator's final relation. A transfer to the floor needs an explicit assisted-transfer protocol revision and a qualified evaluator source before release. The independent SO101 pilot is available after its attended calibration/follow/STOP check. New protocol decisions and quotas require a recorded revision.

## Native training

`physical_training.NativeTrainingData` reads the accepted official LeRobot prefix ranges. It retains the six native state/action units and ordered wrist/top RGB. The explicit `native-two-rgb-128-v1` profile resizes both images to 128 by 128. Action padding stops at each witnessed prefix. Statistics come only from training rows. The official ACT/SmolVLA policy classes, processors and save/reload path are reused. SmolVLA needs a verified local initialization and tokenizer. No physical fitting is eligible from four component attempts or development-only stories.

`python scripts/train_physical_motor.py --corpus CORPUS --output OUTPUT --model act --updates UPDATES --wall-seconds SECONDS` uses the existing native CPU-only reservation. Production data are tagged `hardware_recordings`; explicitly technical native fixtures are tagged `native_replay_fixture` and cannot enter the physical corpus. A one-update technical ACT fixture verified native loading, optimization, checkpoint reload and decoded offline action comparison. It has zero physical admissions or closed-loop manipulations. The two original motor checkpoints and all zero-success evaluations retain their original identities.

The evidence adaptation recipe remains gated on evaluation of the first admitted native histories. Simulation evaluation requires its own declared simulation profile. Physical policy execution still requires native checkpoint qualification, attended ownership and STOP.
