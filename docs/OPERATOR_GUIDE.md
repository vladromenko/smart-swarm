# Homebrain operator guide

Run [Smart_Swarm.command](../Smart_Swarm.command) in a terminal on Homebrain and leave it open to validate recordings. Enter **s** for the card and saved count, and **o** to open the existing [SO101 Studio recording screen](http://127.0.0.1:8020/). Select **Smart Swarm / SO101 pilot attended pilot**, native ID **`<local Studio dataset ID>`**. Use **wrist and top** in that order. The recording screen opens with no dataset selected when the recorder is idle.

## Attended preflight

Open `./Smart_Swarm.command` or choose Smart Swarm (4) in Robot Lab. The launcher displays live recording readiness on startup. Press `d` to refresh it, `w` for the current three-robot story block, or `r` to start or resume the next story. The readiness check reads the cameras in wrist-then-top order and shows hardware owners, available space, the native exporter and both mobile clock states. The native recorder checks its own reservation when the attended attempt starts.

Press **v** or run `./smart-swarm pilot --framing` with the native camera-only preview active and Studio control idle. Open the reported review page to see the two local JPEGs side by side. The receipt records the native camera identity, frame time bounds and STOP generation. Use this review to prepare the setup and use the attended Studio check to confirm reach and wrist visibility at pickup and release.

Run `./smart-swarm status` for current simulation progress, saved evaluation counts and recorded physical attempts. The motor section shows completed validation candidates, the selected checkpoint, and separate fresh-run progress with the corresponding evaluation receipt. Run `./smart-swarm pilot --readiness` for the SO101-only device, recorder and attended-check report. That report requires only Studio. Run `./smart-swarm story-recording readiness` for the distributed device report. Add `--probe-mobile` to check the four configured native mobile sensor routes and print a next check for each role. The menu's **d** command shows both reports and includes this read-only probe.

The readiness display estimates space for the next block and the remaining story deck from saved native dual-robot archives. The estimate retains 1 GiB for Explorer and shows the total before closed archives move to secondary storage. At the observed rates, six 60-second captures need 2.76–2.89 GiB including that reserve, and all 24 need 8.02–8.58 GiB. SO101 Studio raw recordings, exports, derived story files and capture overhead use additional space on Homebrain. Check the live numbers between blocks and use the first recordings to measure the combined file sizes.

The capture volume had 11.39 GiB free after the compact simulation recordings were moved to the mounted `/path/to/secondary-archive-volume` volume. Keep that volume mounted when opening the compact raw dataset or loading either preserved SmolVLA checkpoint. The original paths point to verified copies. If the native recorder helper cannot report its destination and capacity, the launcher stops before the Studio recording reservation check.

After a story closes, Smart Swarm verifies its completed Explorer archive by SHA-256 and preserves it under `/path/to/secondary-archive-volume/physical-native/explorer`. Explorer keeps serving it by its original capture ID. `story-recording status` shows the stored path and byte count for each moved archive. If secondary storage is unavailable, the launcher shows the pending reason and checks again at **q** or when reopened. Keep the existing volume mounted for archive replay. 2. Clear the motion area and tape the cube start, open bin footprint and neutral arm pose. The top view should cover both the cube and the receiving area. Run Studio **Preflight** (`Проверить перед записью`) and retain the saved calibration.

## Four recording cards

In Studio use **Start recording** (`Начать запись`). Once Studio reports the episode is recording, use the native leader to grasp the cube, carry it clear of the surface, then lower, release and withdraw. Use **Save episode** (`Сохранить эпизод`) before leaving a completed attempt. Wait for motion and recording to stop before resetting with hands in the workspace.

| Attempt | Setup and observation |
| --- | --- |
| 1 | Use the taped start and open bin. Establish the nominal reachable placement and verify the terminal relation from a safe view. |
| 2 | Restore the taped cube and bin poses plus the neutral arm pose. Repeat and check whether the cube lifted with the gripper. |
| 3 | Restore the same setup. Repeat and check whether release left the cube in the bin. Save a complete failure and preserve its observed label. |
| 4 | Restore the same setup. Repeat, withdraw to neutral and leave the final scene until the outcome has been checked. |

After saving each episode, use **l** in Smart Swarm while its result is still visible and before resetting or starting the next attempt. Keep Studio auto-advance off. The launcher shows the latest saved attempt and native episode ID, then checks the exact episode receipt again when you enter the outcome. Enter **s** for a stationary cube wholly in the bin and clear of the gripper after native-arm motion alone, **h** for the same final result with manual placement assistance, **f** for failure, or **Enter** if unclear. If you skip an attempt's outcome, it stays unknown. Keep an interrupted attempt with its native reason and count it as one of the four. Finish the recording session with the native **Stop recording** (`Остановить`) control after saving the active episode. Use native **STOP hands** if native following remains active.

Smart Swarm automatically validates and imports after the native session releases its devices. It reuses a completed export for the same saved recordings and requests a fresh Studio export when the saved episode set changes. Motor review requires both recorded native calibration readbacks and an operator-observed native-arm success bound to that exact export episode. The pilot counts review candidates and preserves assisted successes and complete failures with their observed outcomes. Enter **i** for a manual retry or **s** for counts and review results. The four attempts stay in the development split.

If Studio is temporarily busy or export validation times out, the launcher lists the saved recording under `pending_validation`. It retries while Studio is idle, after delays of 10, 30 and 60 seconds. Reopen the launcher to resume the same pending import. If the automatic retries are exhausted, check the displayed reason and use **i**. Review any integrity rejection before proceeding.

The official export allowance scales with the saved frame count and camera count, within 180 to 1,800 seconds. Homebrain's native exporter verified 281 archived wrist images in 27 seconds and 1,768 images across six wrist-only episodes in 108 seconds. A real two-camera block still needs a measured run. Saved-story motor review uses the existing CPU-only reservation. The native exporter retains its per-dataset protection while it reads that dataset. It verifies file hashes and reopens the official reader through the original export path. Saved motor prefixes keep their existing references. Archive receipts are stored beside the accepted export pointer, under `archived-native-exports`. The raw recordings and native export staging still need space on the recording volume. It separately reopens the first and last RGB pairs. The review records actual observation gaps and camera ages. Studio records group goal transmission and measured follower state separately. A temporary consumer failure keeps the completed replacement staged for the next check or launcher restart. A source change defers recovery until the native recording set is stable. Use pure colors distinct from the cyan and violet carrier marks. Keep the two station cards fixed and visible to both mobile cameras, with clear horizontal separation. 1. Prepare the indicated scene and confirm the startup prompt with Enter. In Studio, explicitly start the episode and demonstrate the card. Report the placement boundary, including the earlier insertion on F3. Save the episode and stop native control while keeping the container still. Saving Studio has its own time window. You can return to the menu and resume the card here.
2. Press Enter when Studio has saved and stopped. The launcher checks the matching raw episode and starts the read-only Explorer capture for 60 seconds. 3. Hold the settled destination for three seconds before confirming so Tank can record the final view. Keep the scene unchanged while ROSMASTER observes it and Explorer finishes. The launcher checks the native readback and the private timing windows. If the time or footage runs out, the saved Studio data remains available and an incomplete story retains its reason.
4. Reveal the terminal relation only when prompted. Keep Studio's top preview available for the evaluator clip. Leave any outcome unknown if you cannot see or establish it. Reset only after the launcher confirms that it saved the result.
