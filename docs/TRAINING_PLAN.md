# Training plan

SO101 placement is the first motor development skill. The 30 Hz simulated target is recorded at its decision time and applied after a one-control-period lag. The native LeRobot export uses two authorized RGB streams and six measured state features. The action feature contains requested setpoints. The export validates hashes, near-uniform sim time, camera count, independent split ancestry and padded action chunks after reopening.

Use `generate-motor`, `export-motor`, `train` and `evaluate` from the project CLI. Development runs use CPU and local pinned runtimes. The experiment has an independent data root. Train-only preprocessing statistics are produced by export of the train split. Validation and held-out resets are separate. Checkpoints may be reopened only with their serialized policy, processor, action and feature configuration.

The small ACT pilot uses a compact Transformer configuration and an unfitted ResNet18 initialized as part of training. The SmolVLA pilot uses pinned local pretrained weights with matching wrist and station inputs. The first unmodified CPU run hit a BF16 BLAS fallback before an update. The tested CPU adapter casts parameters to FP32 before the official trainer prepares the optimizer. The pilot uses 256-pixel padded inputs and two denoising steps. The pipeline configurations have caps of 5,000 ACT and 2,000 SmolVLA updates or two hours. Recheck batch throughput and simulation closure before that run. Use the platform's verified compute reservation before GPU training. Update the run ledger after each successful checkpoint reload and closed-loop result.

The planned evidence learner is a frozen encoder with a causal head and separate event and reveal supervision. B1 uses a fixed untrained RGB observation factor. The presence of motor checkpoints does not pass the evidence-model gate.

The checkpoint reload and evaluation process receives only the two local image tensors, native measured state, and fixed motor instruction. This pilot uses ten held-out cube reset seeds with pickup points and sliding friction varied independently of the training worlds. The offline validation loss uses eight sampled frames from two distinct validation worlds. Model-specific losses have different definitions. SmolVLA's pilot action noise used the worker's default RNG state.
